# 盲审协议：基准参考查询（金标）的人类专家复核

**版本**：`ITEMS.md` 与 `RESPONSES.csv` 冻结于 2026-09-06，内容哈希记录在案；本协议 2026-09-07 补入运行方式与英文版，判定词汇与判据未动。
**给谁看**：受邀的 SQL 专家。本包就是你需要的全部材料：协议、条目表、答卷、`run.py`，以及 17 个数据库。
**预计工时**：153 项，每项 2 到 4 分钟，合计约 5 到 10 小时。可以分次做。

> 英文版见 `PROTOCOL_EN.md`，两版内容一致。

## 1. 你要判什么

对每一项，你会看到：一个自然语言问题，它所属的数据库，以及**基准自带的、被当作标准答案的那条参考查询**。

**你的任务只有一个：这条参考查询有没有正确回答这个问题？**

不是判"它写得好不好看"，不是判"有没有更优雅的写法"，是判**它返回的结果是不是这个问题要的答案**。

## 2. 你不会看到、也不该去找的东西

- **没有任何模型输出。** 本包里不存在"另一条候选查询"。这是刻意的：让你在不被任何替代写法牵引的情况下判断金标本身。
- **没有任何先前的判断。** 这批题里有一部分曾被一个自动流程标记为可疑，另一部分没有。**哪些是哪些不会告诉你**，
  条目顺序是打乱的，编号不含任何信息，两类的比例也不公开。
- **请不要去查项目仓库、不要去找先前的标注结果。** 本次复核的全部价值就在于它独立于那个流程。
  如果你在做的过程中不小心看到了先前的判断，请在 `RESPONSES.csv` 的 `note` 里注明该条，我们会把它单列。

## 3. 怎么判：请执行，不要只读

**必须把参考查询在给定的数据库上跑一遍，看它实际返回什么。** 数据库随包附带，`run.py` 可以直接替你跑：

```
python3 run.py Q001                 # 显示 Q001 并执行它的参考查询
python3 run.py --schema world_1     # 某个库的表、列与行数
python3 run.py --db world_1 --sql "select distinct Continent from country"
python3 run.py --check              # 开工前确认包是完整的
```

用命令行 `sqlite3` 也一样，数据库就是 `data/spider/test_suite_database/` 下的普通 SQLite 文件，以只读方式打开。
`ITEMS.md` 的附录另给出每个库的表结构。

很多问题只有跑起来才看得见，例如：

- 字面量大小写与库里存的不一致，条件永远不成立，返回空表
- 数值存在 TEXT 列里，`ORDER BY` 按字典序排，`'9'` 排在 `'100'` 后面
- 问"最年轻"却用了 `MAX(age)`
- `JOIN` 少了 `ON`，成了笛卡尔积
- 过滤条件取反了
- 问"所有的 X"而查询漏了一列
- 集合运算（`INTERSECT` / `EXCEPT`）做在名字上而不是主键上，同名不同实体被合并

以上是可能出现的形态，**不是清单，也不代表这些形态一定在这批题里出现**。请按你自己的判断来。

## 4. 判定词汇（`verdict` 列，四选一）

| 值 | 含义 |
|---|---|
| `gold_correct` | 参考查询正确回答了这个问题 |
| `gold_defective` | 问题有确定的答案，而参考查询算的不是它 |
| `question_underspecified` | 问题本身没有把争议点说死，多种写法都站得住，参考查询是其中之一 |
| `cannot_judge` | 无法判断，请在 `note` 里写清卡在哪里 |

**`gold_defective` 与 `question_underspecified` 的分界是本次复核最关键的一条，请按这个测试来判**：

> 你能不能把这个问题**唯一确定地**说成"它要的是什么"？
> 能，而参考查询返回的不是那个 → `gold_defective`。
> 不能，几个讲道理的人会写出不同的查询、且都忠实于问题 → `question_underspecified`。

**举例说明分界**（构造的例子，不来自本批）：问"列出所有员工的姓名"，而金标只返回了姓不返回名，
这是 `gold_defective`，因为"姓名"在这个 schema 下有确定所指。问"列出主要的几个部门"，
而金标取了人数前三，这是 `question_underspecified`，因为"主要"没有被定义。

## 5. 其余两列

- **`defect_type`**：仅在 `gold_defective` 时填，从下列取一个，取最主要的那一个：
  `case_sensitivity`、`text_column_numeric_or_ordering`、`wrong_extremum`、`missing_join_condition`、
  `wrong_or_negated_filter`、`incomplete_projection`、`wrong_set_operation_key`、`wrong_grouping`、`other`。
  选 `other` 时请在 `note` 里说明。
- **`borderline`**：`yes` 或 `no`。**这一列很重要，请如实填。** 只要你觉得"换个人可能会判成另一个值"，就填 `yes`。
  后续分析会分开报告非难判的那部分，所以标 `yes` 不会让你的判断被打折，它让结果更可信。
- **`note`**：一句话说明理由。`gold_defective` 与 `cannot_judge` 必填，其余可选。

## 6. 两位专家，独立判，最后裁定

理想配置是**两位专家各自独立完成全部 153 项**，互不通气，然后：

1. 计算两人的一致率与 Cohen's κ，作为本次复核自身可靠性的指标；
2. 只对**不一致的条目**做第三轮裁定（第三人，或两人讨论后共同定），一致的条目**不得改动**；
3. 分析用裁定后的标签。

如果只能请到一位专家，本次复核仍然有效，但 κ 无法计算，这会作为限制写进论文。
